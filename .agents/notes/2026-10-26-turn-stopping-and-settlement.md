# 决策：续跑在 turn-stopping 排队，放弃时不写收件箱（2026-10-26）

状态：生效

## 问题

要"自动补发一条消息让回合继续"，宿主里有几个位置可以插手。选错位置的失败是静默的：消息发出去了，但回合没继续，或者回合继续了，但父 agent 被误导。

## 决策

**续跑消息在 `agent/turn-stopping` 里排队**，且只在那一处。

**到达上限时不向收件箱写任何东西**，只记一条 warn。

## 替代方案（强制）

- **在 `session/event` 的 `turn/end` 监听里排队**：该监听在事件发布期间触发，此时日志仍被占用，再追加收件箱事件会被拒绝（append 不可重入）。
- **在 `agent/status` 变 idle 时排队**：那时回合已关、agent 已停，补发要重新唤醒驱动；更要紧的是给子 agent 的结算留出了竞态窗口——子 agent 的结算条件是"空闲 **且** 收件箱为空"，晚一步它就已经结算并向父 agent 报告"结束了"。
- **用 `steer` 而不是 `followup`**：`steer` 写 `next-step`，会被同一个（刚刚空转结束的）回合认领，回合记账变复杂；`followup` 的语义正是"独占一个新回合"。
- **到达上限时发一条可见提示进收件箱**：会挂死子 agent——它的收件箱永远非空，结算永远不 ready，父 agent 永远收不到通知。这比原来的空转更糟。

## 影响

- "三次之后才告诉父 agent"因此**不需要额外代码**：续跑消息在回合关闭前进入收件箱，子 agent 就一直不结算；上限耗尽时不再写入，收件箱自然变空，结算与通知随之上路。
- 代价：上限耗尽那一刻，界面上没有一条显式"我放弃了"的消息，只有第 3 条续跑消息的摘要 `Auto-continue 3/3` 和一条宿主日志。
